# 团队共享平台部署

## 先说结论

现在平台已经从“只绑定本机 `127.0.0.1`”升级为可以绑定 `0.0.0.0` 的团队服务。组员访问的是同一个服务端，共用账号、任务队列、文件存储和报告。

共享平台仍然需要一台持续开机的电脑或服务器作为主机。它不会自动变成公网服务，具体有三种运行方式：

| 方式 | 适用场景 | 访问范围 | 建议 |
|---|---|---|---|
| 本机局域网 | 组员在同一 Wi-Fi/校园网 | 同一网络内 | 当前最快 |
| 实验室服务器 | 主机长期在线 | 校内或经 VPN | 推荐正式使用 |
| 云服务器 | 组员不在同一网络 | 公网/域名 | 必须加 HTTPS 和访问控制 |

## 当前电脑局域网启动

先安装平台依赖：

```powershell
.\scripts\setup.ps1 -Team
.\.venv\Scripts\python.exe -m pip install -e .
```

启动：

```powershell
.\scripts\start_team_platform.ps1
```

脚本会显示本机地址、组内访问地址和自动生成的邀请码。组员只有在同一网络且 Windows 防火墙允许 TCP 端口时才能打开。

当前电脑的候选网络 IP 已在启动脚本中自动列出。不要直接把这个 IP 发给校外人员，也不要在没有账号控制的情况下把端口映射到公网。

## Docker 部署

复制环境文件：

```powershell
Copy-Item .env.example .env
```

编辑 `.env`，设置随机邀请码和长随机密钥。可以这样生成密钥：

```powershell
$bytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
[Convert]::ToHexString($bytes).ToLowerInvariant()
```

启动：

```powershell
docker compose up -d --build
```

数据保存在 Docker volume `eeg_team_data`，容器重建不会丢失账号和报告。备份时使用：

```powershell
docker run --rm -v eeg_team_data:/data -v "${PWD}:/backup" alpine tar czf /backup/eeg-team-backup.tar.gz -C /data .
```

## 放到公网时

不要直接用 `http://公网IP:8000` 作为长期入口。推荐结构：

```text
组员浏览器
   ↓ HTTPS
Nginx / Caddy
   ↓ 内网 HTTP
FastAPI 平台
   ↓
/data 持久化目录
```

必须设置：

- `EEG_COOKIE_SECURE=1`；
- 复杂的 `EEG_INVITE_CODE`；
- 至少 32 字节的 `EEG_COOKIE_SECRET`；
- 反向代理只暴露 HTTPS；
- 服务器操作系统防火墙只开放 443；
- 定期备份 `/data`；
- 不把 `team_data/`、原始数据或 `.env` 提交到 Git。

公网部署会涉及服务器账号、域名、证书和费用，需要团队/导师确认后再进行。当前工作区不能替用户申请云服务器或域名。

## 账号规则

- 第一个注册账号自动成为管理员。
- 之后注册必须填写团队邀请码。
- 任务日志对所有已登录成员可见。
- 关闭浏览器不会停止后台处理；只有服务进程被终止时任务才会中断。
- 服务重启后，排队中和处理中被中断的任务会自动重新排队。

## 容量和备份

- 默认单文件不超过 200 MB，可在 `EEG_MAX_UPLOAD_MB` 中调整。
- 处理结果包含 `processed.csv`，通常明显大于输入文件；不是每次都要长期保留大文件。
- 建议每 1—2 周备份一次 `team.db`、报告和重要特征文件。
- 团队数据目录不应同步到公共网盘；受限数据遵守原始许可。
