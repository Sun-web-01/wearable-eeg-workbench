# 平台建设说明

## 为什么不是一开始就做完整大创 Web 产品

项目最终产品需要“数据导入—任务提交—后端处理—状态日志—结果可视化—报告导出”，应由成员 C/D 主责。成员 A 当前最缺的不是再写一个业务后台，而是可信的数据处理链路。

因此当前平台只解决一个问题：**一份 EEG/IMU 数据能不能进入建模，以及为什么。**

## 平台三层结构

| 层 | 负责人 | 当前状态 | 技术 |
|---|---|---|---|
| 数据验收与预处理 | 成员 A | 已搭建 | Python、NumPy、Pandas、本地 Web |
| 正式科研处理 | 成员 A；成员 B 联调 | 已接入 | MNE、SciPy、scikit-learn |
| 最终产品与实时展示 | 成员 C/D；成员 B 接入模型 | 后续 | FastAPI/React/Vue、BrainFlow、LSL |

## 数据接口契约

成员 C/D 只需按以下约定接入：

1. 上传 CSV；无时间列时提供 `sample_rate`。
2. 后端调用 `process_dataframe()`。
3. 返回 `report`（质量、对齐、窗口、特征）和 `html_report`。
4. 下游读取 `features.csv`，不重新解析原始 EEG。
5. 处理失败返回用户可理解的错误，不把原始异常栈展示给用户。

## 当前不做

- 不在浏览器内完成 ICA；
- 不在平台中执行用户提交的任意 Python；
- 不把模型准确率写进数据质量报告；
- 不在没有真实数据与导师确认时宣称医疗级判断；
- 不把需要成员 C/D 完成的任务重新塞给成员 A。

## 实时版依赖

后续实时采集层使用 `requirements-realtime.txt`：BrainFlow 负责设备连接，pylsl 负责多流时间同步，FastAPI/uvicorn 负责把离线处理模块包装成团队后端接口。当前没有真实硬件，不提前安装或声称已完成硬件联调。
