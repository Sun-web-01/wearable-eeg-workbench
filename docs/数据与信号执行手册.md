# 数据与信号执行手册

这份手册用于推进“面向运动干扰的可穿戴脑电多模态融合与跨个体脑状态识别研究”。目标是让团队知道下一项实验为什么做、数据怎样准备、结果怎样验收。

## 1. 当前确定的范围

项目已收敛为四项技术工作：

1. 选择两类具有明确实验操作和标注依据的脑状态或认知任务状态；
2. 研究 EEG 与 IMU 多模态融合；
3. 比较不同运动或干扰条件下的识别鲁棒性；
4. 评价严格独立受试者上的泛化能力，并探索个体化校准。

“睡眠、疲劳、专注、放松”是早期备选方向，不是当前已经选定的四分类。

## 2. 第一阶段：确定两类状态

团队需要比较 2 至 3 个候选组合，而不是先决定模型再看数据。每个候选组合都要填写：

| 项目 | 核查内容 |
|---|---|
| 实验操作 | 受试者具体做什么，提示和时序能否重复 |
| 标注依据 | 事件、行为结果、量表或公开标签的来源 |
| 公开数据 | 是否存在可用数据，许可和申请条件是什么 |
| 数据规模 | 受试者、session、试次和有效窗口数量 |
| 数据模态 | 是否同时有 EEG 和 IMU |
| 标签质量 | 边界是否清楚，是否有重叠或未知类别 |
| 时间同步 | EEG、IMU、事件时间能否对齐 |
| 运动条件 | 是否能设计静坐与至少一种动态条件 |
| 跨个体评价 | 是否有足够受试者完成独立测试 |
| 复现成本 | 招募、设备、采集时长和标注成本 |

Tang 2025 是会议中推荐核查的新范式线索，但目前没有完成正式核验。确定使用前必须补齐准确标题、官方链接、许可证、样本规模、任务操作、标签粒度和 EEG/IMU 信息。

阶段交付：

```text
state-selection.md
dataset-comparison.csv
protocol-draft.md
```

## 3. 第二阶段：建立统一数据流程

统一格式至少包含：

```text
time_s
eeg_*
acc_*_g
gyro_*
state_label
motion_condition
```

其中 `state_label` 使用团队最终确定的两类正式标签；尚未定稿时可用 `state_a`、`state_b` 占位。`motion_condition` 记录静坐、转头、上肢动作或步行等条件。

当前设备采集页已经可以记录两类状态标签，但 `motion_condition` 还需要写入实验记录，或者作为 CSV 列随数据提供。正式实时系统应在采集界面增加运动条件字段。

每次数据入库检查：

- 来源、许可和匿名编号；
- EEG/IMU 通道、单位和采样率；
- 时间轴、重复点和缺口；
- 标签与事件时间是否对应；
- 运动条件是否记录；
- 文件哈希和实验配置。

阶段交付：

```text
data-manifest.csv
quality-report/
sync-check.md
features-dictionary.md
```

## 4. 第三阶段：建立基线与融合模型

至少完成三组模型：

1. EEG 单模态基线；
2. EEG + IMU 融合；
3. 加入运动门控或校准的改进版本。

基础模型可以使用 SVM、随机森林或逻辑回归，深度学习基线可使用 CNN 或轻量 Transformer。模型复杂度不是主要目标，关键是控制变量并解释融合收益。

每组实验必须保持：

- 同一数据划分；
- 同一评价指标；
- 同一随机种子策略；
- 同一预处理版本；
- 同一测试集。

阶段交付：

```text
data-split.json
model/
results/single-modal.csv
results/fusion.csv
confusion-matrix/
ablation.md
```

## 5. 第四阶段：运动鲁棒性和跨个体测试

### 运动条件

至少设置两种可重复条件，例如：

- 静坐；
- 按提示转头；
- 坐姿上肢动作；
- 受控步行。

记录动作频率、持续时间、设备固定方式和有效窗口数量。

### 跨个体测试

至少完成一次严格独立受试者测试：

- 测试受试者未参加训练；
- 测试受试者未用于调参；
- 数据划分在建模前冻结；
- 个体校准数据与测试数据分开保存。

评价至少包含准确率、宏平均 F1、混淆矩阵，并分别报告不同运动条件的结果。

## 6. 第五阶段：实时原型

实时或近实时系统至少完成：

- 信号流显示；
- 滑动窗口预测；
- 状态结果记录；
- 时间戳日志。

建议参数：

- 滑动窗口 2—4 秒；
- 更新间隔不超过 1 秒；
- 处理延迟目标不超过 1 秒。

延迟统计口径必须写清楚，包括从哪个时间点开始计时、到哪里结束，以及是否包含采集、预处理、推理和页面显示。

## 7. 当前平台能承担的部分

NeuroTeam 已经完成：

- CSV/EDF 上传和预检；
- 时间轴与通道检查；
- 重采样、滤波和工频处理；
- 通道质量和 IMU 运动伪迹检查；
- 窗口特征与可追溯报告；
- BrainFlow 设备采集；
- 任务队列和团队协作。

当前还不能替代：

- 两类状态选择；
- 正式实验范式；
- 模型训练和融合对照；
- LOSO 或独立受试者结果；
- 个体化校准；
- 实时模型推理和延迟验收。

## 8. 每个实验至少留下什么

```text
run.md             目的、假设和实验条件
config.json        固定参数和随机种子
data-split.json    训练、验证、测试划分
report.json        数据和模型结果
features.csv       窗口特征
processed.csv      处理后的数据（按需）
predictions.csv    测试集逐样本预测
metrics.json       准确率、宏平均 F1 等
```

## 9. 完成标准

我的完成不只是“程序能跑”，还要同时满足：

- 两类状态和标注依据清楚；
- 数据来源和许可清楚；
- EEG/IMU 时间同步可追溯；
- 参数、版本、随机种子和划分可复现；
- EEG 单模态与融合模型在同一测试集比较；
- 至少两种运动条件有独立结果；
- 至少一次严格独立受试者测试；
- 实时结果具有明确的更新间隔和延迟统计；
- 报告说明误差来源、局限性和不能证明的内容。

## 10. 协作方式

数据、算法、系统、设备和材料工作会互相影响，但每个人需要知道自己的主要交付物。

- 数据与文档支撑负责格式、质量、特征、报告和复现材料；
- 算法岗负责模型、训练、消融实验和跨个体评价；
- 后端岗负责正式接口、任务服务和数据持久化；
- 前端岗负责采集、结果和实时状态的界面；
- 设备采集变化时，共同确认通道、时间同步和元数据。

任何成员发现文档与实际不符，都可以直接提出修正。重要规则和结果共同复核，避免把岗位边界变成信息壁垒。
