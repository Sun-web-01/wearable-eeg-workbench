# 平台整体说明

项目正式名称为“面向运动干扰的可穿戴脑电多模态融合与跨个体脑状态识别研究”。平台是该项目的数据质量、特征交接和团队协作基础。

项目已确定“两类脑状态 + EEG/IMU 融合 + 运动鲁棒性 + 跨个体泛化”四项主线。具体两类状态尚待团队根据数据支撑、标签质量和实验范式可复现性共同确定。

## 1. 为什么先做数据平台

EEG/IMU 项目最容易出现的问题不是模型代码写不出来，而是数据本身说不清楚：

- 时间轴是否连续；
- 电极是否贴好；
- 某个通道是否一直不动；
- 头部运动是否污染了脑电；
- 训练集和测试集是否来自同一段数据；
- 结果能否用同一输入重新得到。

所以平台先回答：**这份数据能不能进入建模，依据是什么。**

## 2. 一条数据从上传到报告经历什么

```text
登录
  ↓
上传 CSV/EDF 或从设备采集
  ↓
浏览器预检
  ↓
服务端读取与结构校验
  ↓
重采样、滤波、陷波
  ↓
通道质量、时间缺口、运动伪迹检查
  ↓
按窗口提取频带特征
  ↓
生成报告和下载文件
```

后台任务不会因为关闭浏览器而停止。服务进程退出时任务会中断；重启服务后，排队中和处理中的任务会重新排队。

## 3. 平台由哪几部分组成

| 部分 | 做什么 | 通俗理解 |
|---|---|---|
| `team_web` | 登录、上传、任务、设备采集和报告界面 | 组员访问 `/` 看到的网页 |
| `team_admin` | 服务状态、账户、任务、采集和容量管理 | 管理员访问 `/admin` 看到的独立页面 |
| `team_platform` | 账号、任务队列、文件记录和设备连接 | 平台后台 |
| `wearable_eeg` | 读取信号、滤波、质量检查和特征提取 | 数据加工车间 |
| `web` | 本地数据质量界面 | 不依赖团队的本地工具 |
| `tests` | 自动验证流程 | 防止改坏功能 |

## 5. 当前没有做什么

- 没有在网页里执行用户上传的任意 Python；
- 没有用演示数据宣称模型准确率；
- 没有默认把所有原始数据公开；
- 没有保证任意 EEG 文件都能读取；
- 没有完成两类状态的正式分类模型；
- 没有完成 EEG 单模态与 EEG + IMU 融合对照；
- 没有完成运动条件、跨受试者测试和实时推理验收。

## 6. 数据与模型之间的接口

下游模型通常读取：

1. `features.csv`：窗口级特征；
2. `report.json`：参数、质量、通道和时间对齐结果；
3. 原始 session 清单：受试者、日期、任务和标签来源；
4. 数据划分文件：训练、验证、测试如何分组。

`processed.csv` 可以用于复核，但体积较大，不一定提交 Git。模型方向不能只拿到特征表就忽略数据来源和划分，否则很容易出现同 session 泄漏。

## 7. 现实边界

### 质量等级不是准确率

A 级表示本次信号通过规则检查，不代表模型一定准确。D 级也不代表设备坏了，可能只是短片段、电极接触或阈值不合适。

### EDF 能被读取不代表数据一定正确

通道名、单位、采样率和电极位置仍需人工核对。

### 运动门控不是 ICA

当前主要使用 IMU 识别头部运动并拒绝相关窗口。ICA、回归和其他复杂去伪迹方法属于后续研究，需要人工复核。

### 合成数据只能证明流程

演示任务使用固定随机种子生成信号，适合开发和验收，不能用于判断真实脑状态。

### 两类状态还没有定稿

“睡眠、疲劳、专注、放松”是早期探索方向。当前只确定选择两类，具体类别必须以数据、标签和实验操作是否可靠为准。Tang 2025 新范式数据集也需要先核验准确名称、许可、样本和标注。
