# 数据平台建设说明

## 为什么先从数据工作台开始

项目最终产品需要“数据导入—任务提交—后端处理—状态日志—结果可视化—报告导出”。系统方向同学牵头产品建设；我主要负责可信的数据处理链路，并在接口和模型联调时与大家配合。

因此当前平台只解决一个问题：**一份 EEG/IMU 数据能不能进入建模，以及为什么。**

## 平台三层结构

| 层 | 主要推进 | 当前状态 | 技术 |
|---|---|---|---|
| 数据验收与预处理 | 我牵头，大家共同复核 | 已搭建 | Python、NumPy、Pandas、本地 Web |
| 正式科研处理 | 我牵头，模型方向同学参与联调 | 已接入 | MNE、SciPy、scikit-learn |
| 最终产品与实时展示 | 系统方向同学牵头，模型方向同学接入模型 | 后续 | FastAPI/React/Vue、BrainFlow、LSL |

## 数据接口契约

系统方向同学可以按以下约定接入：

1. 上传 CSV；无时间列时提供 `sample_rate`。
2. 后端调用 `process_dataframe()`。
3. 返回 `report`（质量、对齐、窗口、特征）和 `html_report`。
4. 下游读取 `features.csv`，不重新解析原始 EEG。
5. 处理失败返回用户可理解的错误，不把原始异常栈展示给用户。

## 现阶段协同约定

- 不在浏览器内完成 ICA；
- 不在平台中执行用户提交的任意 Python；
- 不把模型准确率写进数据质量报告；
- 不在没有真实数据与导师确认时宣称医疗级判断；
- 数据、模型和系统方向通过接口协同推进；遇到跨方向问题时先一起定位，再明确下一步由谁推进。

## 实时版依赖

后续实时采集层使用 `requirements-realtime.txt`：BrainFlow 负责设备连接，pylsl 负责多流时间同步，FastAPI/uvicorn 负责把离线处理模块包装成团队后端接口。当前没有真实硬件，不提前安装或声称已完成硬件联调。
